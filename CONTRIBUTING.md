# Contributing to the documentation

Keep statements tied to source code, executed tests, supplied academic templates, or cited external sources.

## Rules

1. Do not invent metrics, hardware, training parameters, screenshots, dataset permissions, or individual contributions.
2. Mark unknown academic fields as `[TO BE CONFIRMED]`.
3. Keep upstream authorship and license notices intact.
4. Separate implemented, verified, blocked, and proposed functionality.
5. Cite papers and framework documentation using stable URLs or DOIs.
6. Do not add model weights, datasets, uploaded media, credentials, or template binaries.

Before submitting changes, check Markdown links, scan for absolute local paths and secrets, and review claims against the source repository.
